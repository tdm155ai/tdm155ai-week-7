Run from the repository root with Node, ffmpeg, and ffprobe installed:

```sh
node utils/multicam/sync.mjs 'cam-a.mov@2:00-3:00' 'cam-b.mov@5:00-7:00' --reference cam1 --session interview
node utils/multicam/preview.mjs output/multicam/interview/manifest.json
node --test utils/test/multicam*.test.mjs
```

`sync` creates a new `output/multicam/<session>/` and refuses an existing session. IDs are `cam1`, `cam2`, … in argument order; `--reference` and `--master-audio` accept these IDs (both default to cam1). An audio-only source may be the reference. Windows accept seconds, M:SS, or H:MM:SS, must be at least 1.2 seconds and at most 180 seconds, and should leave half a second of sound on each side of the clap. Quote arguments containing spaces. `--no-preview` saves analysis without rendering. Preview is independently runnable and refuses to overwrite its MP4. All commands use the first audio and first video stream. No dependencies beyond Node and FFmpeg.

## Version 1 manifest

`manifest.json` is UTF-8 JSON. Times are decimal seconds, ranges are half-open, and unknown values are `null`. Paths to originals are absolute local paths; artifact paths are relative to the session directory. This is a local CLI contract, not permission for a web endpoint to serve arbitrary paths. A2 must register/copy permitted media through its media layer.

**One offset convention: `timelineTime = sourceTime + offsetSeconds`.** Source time zero is the file's ffprobe `format.start_time` (or the minimum stream start when absent, else zero). Native presentation time is `sourceTime + timing.originPtsSeconds`. Never reset each stream separately: audio/video start differences belong to the recording. Timeline zero is reference source zero; negative timeline ranges are allowed. For example, an event at reference 3 s and camera 5 s means the camera offset is −2 s. Browser/proxy timing must use the same source zero or declare its origin mapping.

Top-level fields:

| Field | Meaning |
|---|---|
| `schemaVersion` | Integer `1`. Reject unknown versions. |
| `sessionId`, `createdAt` | Directory name and ISO time. |
| `status` | `matched` or `needs-review`; matched means local audio evidence, not human approval. |
| `referenceSourceId` | Reference source whose offset is zero. |
| `masterAudio` | `{ sourceId, streamIndex }`; keep this track continuous through camera switches. |
| `sources` | Objects described below. |
| `analysis` | Method, sample rate, thresholds and candidate cap. Quality scores are correlations, not probabilities. |
| `anchorTimelineSeconds` | A matched event on the reference timeline, or null. |
| `drift` | `{ status: "unverified", note }`; single-event sync never verifies a whole take. |
| `preview` | Status, relative MP4 path, timeline start/end, source IDs in left-to-right order, audio source ID; or reason unavailable. |
| `cuts` | Initially `[]`. A2 may write sorted `{ timelineSeconds, sourceId }` entries: each camera holds until the next cut or an explicitly chosen export end. No implicit cut at zero. Reject duplicate times, unknown IDs and cuts into unavailable video. |

Each source has `id`, `path`, `searchWindow: {startSeconds,endSeconds}`, `timing`, `offsetSeconds`, `eventSourceSeconds`, `match`, and `proxy: null`. A future proxy slot is `{path, sourceStartSeconds, durationSeconds}`: proxy time zero maps to `sourceStartSeconds` in original source time. No proxies or full aligned originals are generated by A1.

`timing` keeps complete ffprobe `format` and `streams` metadata (including native stream start times, time bases, frame rates, durations), `originPtsSeconds`, selected `audioStreamIndex` / `videoStreamIndex`, and `audioRange` / `videoRange` in source seconds. Range end uses stream start + duration when available, otherwise container start + duration as an estimate (`endEstimated: true`); container metadata can overestimate usable ranges. A2 should verify end boundaries against decoded media before exporting. Nominal frame rate is metadata, not a promise of constant frame rate or sample-accurate video cuts.

`match` has `status`, `reason`, `candidates`, and `transients`. Candidate evidence includes reference/source event seconds, offset, waveform correlation, surrounding-audio correlation excluding the clap, and combined score. Different candidate pairs at the same offset (within 50 ms) are grouped. An accepted offset requires full correlation ≥0.65, surrounding correlation ≥0.55, and a score lead ≥0.12 over the next distinct offset. Unresolved offsets and event positions are null; A2 must not coerce null to zero. The reference retains zero even if another source cannot match.

## Matching and limitations

Only each requested window is extracted as mono 8 kHz analysis audio. FFmpeg seeks with native timestamps retained, trims to the absolute window, then subtracts the common file origin plus window start; resampling pads stream-start gaps instead of silently moving audio earlier. Ten-millisecond RMS rises nominate at most 12 transients, separated by 300 ms. Candidate pairs are refined by normalized waveform correlation within ±25 ms, using up to half a second of surrounding sound on either side. Polarity inversion is allowed. A second score excludes ±60 ms around the clap; isolated clicks with silence around them cannot qualify.

This deliberately conservative method can refuse recordings with different microphone responses, strong echo, automatic gain changes, music, sparse surrounding sound, or too many transients. It is not a general speech alignment model. Exit code 2 means review the printed candidates, narrow the windows, or synchronize manually in an editor using a visible clap. Exit code 1 means invalid input/tool failure. No automatic manual-offset override is provided. Missing audio streams are recorded as unresolved rather than guessed.

Matched sessions get a short H.264/AAC side-by-side check at 30 fps, with one chosen audio track, cropped to overlapping available ranges around the anchor. Audio-only references are omitted from the picture. Video panels follow source order. Preview failure does not erase the manifest; it is recorded and returns code 1. Watch and listen before using the offsets. Long-take drift is always unverified here: check a second shared event near the end (in a separate session with the same reference) and compare offsets before claiming whole-take sync. Drift correction, camera switching, and cut-list rendering belong to later work.
