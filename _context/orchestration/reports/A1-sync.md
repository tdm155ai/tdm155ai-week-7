## What I built

`utils/multicam/README.md` defines the version 1 manifest and timing contract. `core.mjs` probes sources, extracts only named mono analysis windows, detects transient candidates, and checks normalized waveform correlation plus surrounding audio with the clap excluded. `sync.mjs` supports two or more sources, a selectable reference and master audio, fresh named output sessions, printed evidence, unresolved matches, and an automatic check preview. `preview.mjs` also runs independently, aligns video panels without resetting each stream's start separately, and uses one continuous master audio track. `nextjs/content/resources/video/multicam-sync.md` is the requested unlinked student page.

Seven Node tests passed on Node v25.6.1 and FFmpeg 9.0.2. All fixtures are generated by FFmpeg lavfi under ignored `output/multicam/`; no media is committed. Tests cover parsing, both offset signs, independent window starts, nonzero native timestamps, unequal audio/video starts, changing reference, source preservation, session overwrite refusal, missing claps, mismatched surrounding audio, isolated clicks, ambiguous repeated claps, silent/missing audio, an audio-only reference, AAC encoding, and gain/polarity changes.

Measured fixture offsets were −2.000000 s and +1.000000 s, both with zero measured error at the 8 kHz analysis resolution (125 microseconds). Reversing reference recovered +2 s. A shared pink-noise fixture trimmed by 1.137 s, encoded to AAC and attenuated/inverted recovered +1.137000 s with zero measured error and score 0.995378. These are generated fixtures, not estimates of accuracy on real camera microphones.

Decoded preview verification found all three visual flashes at 1.000 s and the single master-audio click at 1.000 s. The preview has three 480×270 panels and one audio stream. I inspected an extracted frame at the simultaneous flash; this was a static image inspection, not human playback/listening. The manifest keeps `humanChecked: false`.
