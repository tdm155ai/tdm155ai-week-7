## The task

1. **The manifest format first.** Write `utils/multicam/README.md` defining the session manifest (schema version, sources with IDs and paths, ffprobe timing metadata including stream start times, one offset convention stated once, match evidence, a slot for proxies and a master audio choice, and an empty `cuts` list for A2). Units in seconds as decimals, plus frames where useful.
2. **The sync command:** `node utils/multicam/sync.mjs` taking two or more files, each with a search window in source time (for example `cam-a.mov@2:00-3:00 cam-b.mov@5:00-7:00`), and an optional reference. It probes with ffprobe, extracts mono analysis audio only for those windows, finds the shared transient, confirms it by comparing the surrounding audio (cross-correlation or similar, your choice of method and dependency; prefer none beyond Node and ffmpeg), and writes `output/multicam/<session>/manifest.json`. It prints the offsets and a match-quality figure; when the match is weak or ambiguous it says so and lists candidates rather than picking one.
3. **The check preview:** a short side-by-side (or stacked) clip around the event, both cameras aligned, one audio track, written to the session folder, so a person can see and hear the sync.
4. **Tests** in `utils/test/multicam.test.mjs` with fixtures generated by ffmpeg `lavfi` (tone or noise plus a click at known times, nonzero start timestamps, both offset signs, a missing clap). Run with `node --test utils/test/multicam*.test.mjs`. Don't commit media.
5. **A student-facing doc**: `nextjs/content/resources/video/multicam-sync.md` (frontmatter per `AGENTS.md`), explaining how to ask Claude to sync two cameras with this tool, in a page or less. Link it from nothing else; the orchestrator will place it.

`utils/` may not exist when you start (task B is copying week 6's in parallel). Create only `utils/multicam/` and your test file; don't touch `package.json` or other `utils/` files. In your report, give the `package.json` script line you want.
